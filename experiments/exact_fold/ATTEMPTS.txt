Attempt 1: Size scout (completed)
scout.py evaluates identity, XOR, first differences and second differences,
with/without byte-plane transposition, using the existing SNZ compressor.
All transforms operate on uint64 bit patterns, including REAL values. They do
not subtract floating-point numbers. Every residual and every source byte is
retained. A 1024-word quadratic integer fixture shrank from an existing stored
column frame of 2864 bytes to a 252-byte candidate. A floating timestamp fixture
went from 6240 to 314 bytes. Random words did not improve. These are constructed
fixtures and size comparisons, not native throughput evidence.

Attempt 2: Shared string spans (completed, not promoted)
Deterministic bounded overlap pooling stores (offset,length) for every original

The prototype is retained in scout.py for a possible specialized window store.
It is not the factor-two algorithm in family 128: that construction explicitly
enumerates O(L^2) substring vertices and is not a suitable hot write path here.

Attempt 3: Native tiled residual folds and canonical merges (completed)
fold.c uses 128-word tiles aligned to absolute logical positions. Per tile it
chooses exactly the smallest complete encoding among raw words, base offsets,
first differences, second differences and XOR differences. Residual minima,
packed widths, seeds and headers all count; ties use a fixed mode order.
Every operation is in Z/(2^64). NULL maps belong to the containing column frame.

Why inversion is exact: a first difference d_i=x_i-x_(i-1) is inverted by
x_i=x_(i-1)+d_i, modulo 2^64. A second difference is inverted using the prior
two words. Zigzag is a bijection on 64-bit words. Removing an unsigned minimum
and bit-packing the remaining range also loses no information. Applying the
same identities to IEEE bit patterns preserves all bits without floating error.
This elementary derivation is independent of the new manuscripts' validity.

Why merging is reproducible: each absolute tile has a deterministic encoding.
Joining adjacent intervals leaves every interior tile untouched. If the join
cuts a tile, at most 128 words are decoded and that single tile is re-encoded.
Therefore merge(fold(A),fold(B))=fold(A followed by B) at matching origins.
Induction gives identical bytes for every ordered parenthesization. Order is
preserved: merging is associative over adjacent intervals, not commutative.
Materialized merging copies compressed bytes; it is not O(1) and not zero-copy.

Attempt 5: Bounded comparison instead of fully encoding the loser (retained)
A 128-word probe rejects weak candidates. The full fold must first be at most
half the legacy uncompressed frame size. The folded candidate is compressed,
then the legacy compressor runs with a stopping bound. Its written output plus
pending literal bytes is a monotone lower bound on its eventual coded length.
If that bound AND the raw fallback size exceed the comparison threshold, the
legacy attempt stops. Otherwise it finishes normally. Thus selection still
guarantees at least 16 bytes and 10% saved against the actual legacy encoding;
the probe can miss an opportunity but cannot select a larger frame.

Retained functionality and usage
The new native implementation lives in ext/sqlnew/fold.c and is registered by
the normal SQLNEW build. No Python or NumPy is required at engine runtime.

  sqlnew_fold(word_blob [, absolute_word_origin])
  sqlnew_unfold(folded_blob)
  sqlnew_fold_merge(left_folded_blob, right_folded_blob)

Inputs to fold are little-endian 64-bit words (blob length divisible by eight).
They may be signed integer representations, IEEE bit patterns, or opaque words.
The default origin is zero; adjacent chunks must use matching absolute origins.
The maximum raw input is 64 MiB. Empty folds act as identities at their origin.
The functions preserve the complete original bytes, including NaN payload bits,
infinities and negative zero when treated as opaque words. Columnar REAL values
continue to follow the existing finite-value contract.

For automatic numeric column selection, explicitly enable it on the connection:

  SELECT sqlnew_columnar_folding(1);
  CREATE VIRTUAL TABLE readings USING sqlnew_columnar(t INTEGER, value REAL);
  -- Ordinary INSERT/UPDATE/SELECT/compaction continue to use the existing API.
  SELECT sqlnew_columnar_folding();   -- current setting
  SELECT sqlnew_columnar_folding(0);  -- disable future folded writes

The setter returns the previous setting. New connections default to zero.
Reading already-folded columns does not require enabling new folded writes.
This is an experimental rollout candidate, not a change to the stability claim.
There was no change to src/, the pager, the file signature, or SQL semantics.
Old executables do not decode the new CSC codec 2; use this build for files
written with folding enabled. No mass rewrite or migration was performed.

Format notes (all integers little-endian)
SFL1 header: magic at 0 (4 bytes), tile log2=7 at 4 (1 byte), zero bytes 5..7,
unsigned absolute origin at 8 (8 bytes), word count at 16 (8 bytes), zero 24..31.
Tiles terminate at absolute multiples of 128. Their word counts are inferred
from origin and total count. Each has a 4-byte mode/width/zero/zero prefix.
Mode 0 stores raw words. Mode 1 stores residual minimum then bit-packed offsets.
Modes 2/4 store minimum, one seed, then first-difference/XOR residual offsets.
Mode 3 stores minimum, two seeds, then second-difference residual offsets.
Difference modes use reversible zigzag on unsigned modular differences.
Offsets are least-significant-bit first, with zero unused bits. A fixed ordering
of equal-size candidates establishes a unique encoding for each tile.
SFL1 itself has no checksum; automatic column storage retains its SNZ1 wrapper.

CSC1 numeric codec 2: original type, slot count and NULL bitmap retained;
width=0 and header bytes 8..27 zero. Payload is one SFL1 frame at origin zero,
containing only non-NULL words in slot order. The usual SNZ1 wrapper surrounds
the complete CSC1 frame. Non-numeric and affine encodings are preserved.

Structural direction, still exploratory and not implemented:
The user clarified that registering objects in another table does not capture
the idea. The application's underlying data model and operations should embody
the structure. Symmetry may survive even when physical spacing and payload
sizes are asymmetric. The earlier catalogue/resolver-first suggestion is
superseded as the proposed starting point. Shared descriptive reference data
can remain useful without being the mechanism that creates the lattice.

One interpretation to explore is a native region structure with uniform rules
for selecting, slicing, subdividing and composing along each coordinate axis.
Rows, columns and planes would be selections of that structure. Its own
directories would describe occupied regions and directly locate child regions
or payload extents. Regular adjacency would follow from the addressing rules;
irregular connections could be stored as structural links. Logical symmetry
does not require equal byte lengths, identical codecs or identical access costs.
Specific semantic relationships still require explicit information; position
alone cannot establish them. Meanings of axes remain open.

Potential retained inner layers: SNZ byte compression, SFL exact word folding,
typed payload encoding, and the existing pager as an initial backing store.
Sparse-update and summary approaches can inform adapters, but their present
implementations assume table columns and rowid groups. CsBlock contains fixed
column arrays and masks; the existing storage engine is not already symmetric
across three axes. Ordered fold merging remains valid only for contiguous
word streams with compatible origins. Axis changes must preserve ordering
contracts, especially for overflow-sensitive sums and floating arithmetic.

A possible structural experiment would store unequal-sized regions directly
in a persistent region directory, with no per-cell registration table. Select
the same occupied cells through different orders of axis slicing, including
sparse gaps and multi-page payloads. Split and recompose regions while checking
exact cell identity, explicit versions and recovery. Numeric leaves can use
the existing fold codec. Measure directory bytes, payload bytes touched and
rewrite cost. Native relationships, network transport and encryption can be
explored separately; this is an option, not a committed feature list or rewrite.

Implementation and scope
experiments/exact_fold/regions.py is an isolated Python representation scout
calling the current native SQLNEW compression/folding functions. It writes
self-contained binary region packets, with direct byte offsets to children.
There is no SQL object-registration table or separate per-cell address table.
No main-engine or doc2sql source was changed in these attempts. The work was
solo, with direct recovery experiments and no pytest or security suites.

Each packet has a 64-byte root containing dimensions, extent, root offset,
root anchor and occupied-cell count. A region splits uniformly along X/Y/Z
into up to eight occupied children. Empty children are omitted. The present
leaf extent is 8x8x8 logical words, while its encoded byte length is variable.
Partial leaves contain an occupancy bitmap; an absent cell differs from an
occupied zero. Leaves preserve arbitrary 64-bit patterns. This scout does not
yet implement multi-page text-valued cells, arbitrary relationship links,
incremental durable updates, SQL query execution, encryption or networking.

Each record has an 8-byte kind/flags/mode/length header. A branch contains a
one-byte child mask and a 16-byte (child byte offset, value translation) pair
for each occupied child. Leaf payloads use the smallest of raw bytes, SNZ,
SFL, or SNZ(SFL). All packet sizes below include directories, record headers,
occupancy maps, translations and payloads. Source arrays and encoder caches
are not needed by the decoder. Generic decoder code is shared in every case.

The reference comparison is a standalone linear packet using the same four
codec choices, searching all SIX axis orders and recording the selected order.
It includes its 64-byte header and compressed occupancy map where needed.
Both linear and region packets were written and reopened for exact recovery.
These comparisons are complete experimental packet sizes, not whole SQLNEW
database sizes and not measured SQL query or network latency.

Attempt 7: reversible differences along multiple axes
Variant regions_delta. Evaluate all eight subsets of X/Y/Z differences per
leaf, preserving boundary seeds, and choose the smallest complete leaf frame.
Differences and inverse prefix sums operate modulo 2^64, so no approximate
fitting, floating arithmetic or quantization occurs. Operators on distinct
axes commute; each one is invertible by prefix sums along that axis.
Quadratic region storage improved to 129,876 bytes, still much larger than
the 21,042-byte strongest linear comparison. Arbitrary source bytes did not
benefit. Rejected as a sufficient standalone improvement.

Attempt 8: share translated structure recursively
Variant regions_shared combines axis differences with exact regional sharing.
Subtract the first occupied word from every occupied word in a leaf. Store
that anchor on the incoming edge. At each parent, store child anchors relative
to its first child's anchor, moving the common anchor to the parent's incoming
edge. Intern identical encoded records by exact byte equality. Equal normalized
leaves and equal normalized subtrees can therefore occupy the same bytes.
Coordinates follow traversal paths, so shared storage does not merge cell
identities. The graph is acyclic: every child record precedes its parent.

For a leaf, value[i] = anchor + normalized[i] modulo 2^64. For a branch,
child_anchor = parent_anchor + edge_translation modulo 2^64. These identities,
the explicit occupancy bitmap and reversible leaf transforms establish exact
recovery inductively. There is no reliance on a hash match alone: dictionary
keys are complete record bytes and equality is checked by the Python mapping.
Canonical rebuild applies to the same values, occupancy, dimensions, options
and traversal order. Axis permutations need not produce identical packet bytes.

Significant failure boundary
One independently changed word per 512-word motif region is only 0.1953125%
of values. It makes every normalized leaf distinct and destroys the sharing:
the packet grows from 14,169 to 2,111,313 bytes. The values still recover exactly;
this is a compression failure, not corruption. Two additional independent
motif/anchor seeds (107 and 128) reproduced these exact sizes. With only ONE
changed value globally, both seeds instead produced 18,273-byte packets, so
sharing survives elsewhere. Do not assume near-equal regions share efficiently.
No exception/residual-sharing mechanism has been implemented in this attempt.

Decision at requested pause
Retain the isolated scout and evidence; do not integrate this structure into
the main engine yet. Structural normalization and sharing can multiply the
existing codec's compression on repeated shapes and reduce repeated decoding.
Exact whole-leaf equality is too brittle under distributed small edits, and
numeric normalization is unsuitable as a compulsory path for arbitrary bytes.
A next direction worth discussing is a shared exact base plus sparse exact
exceptions with a bounded lookup dependency, alongside a byte-preserving
fallback. This is a proposed response to the finding, not work already done.

Implementation
experiments/exact_fold/overlays.py reuses regions.py and the same native codecs.
OverlayWriter automatically keeps a mapping from LOGICAL coordinates to the
latest replacement value or deletion. It never edits the base packet, shared
leaf records, or another occurrence of a shared pattern. Setting a cell back
to its base state removes its change entry. Occupied zero differs from absence.

On sealing a snapshot, the writer encodes two sparse region packets: replacement
values and deletion positions. They can share their own repeated internal
patterns. A 128-byte outer SOV1 header records the base packet's SHA-256,
generation, shape, child packet lengths and number of changed coordinates.
The complete current view consists of the original base plus this overlay.
An empty overlay occupies 256 bytes (outer header plus two empty region roots).
The hash is checked at reader construction to bind changes to the exact base.

For each requested coordinate, a deletion makes it absent, a replacement
supplies the new exact bits, otherwise the original base supplies the value.
Replacement and deletion masks are disjoint. When changes cover an entire
requested selection, the reader skips the base for that selection. All reads
use one consolidated current overlay, never a replay chain of past edits.
Older sealed overlay bytes continue to describe their pinned earlier state.

This is an actual separate change representation, not a registry that merely
names lattice objects. The current SQLNEW column engine already has a related
sparse-patch approach, but ext/sqlnew/columnar_write.inc merges dense patches
at 64 changed slots. No such merge into the immutable base occurs in this scout.
No main SQLNEW or doc2sql source was changed by this attempt.

The sparse overlay presently reuses a DENSE 512-word leaf decoder. Random

Attempt 10: retrieve sparse changes directly
The user redirected the next step toward simplifying retrieval. This attempt
keeps the immutable base and consolidated change semantics, and replaces only

measurements remain intact for direct comparison. A useful retrieval milestone
was reached; further expansion is paused for the requested progress report.

Implementation
experiments/exact_fold/retrieval.py adds SparseWriter and SparseReader. Callers
use get((z,y,x)) for a value/absence or select(bounds) for a region. The reader
resolves current values internally; callers do not inspect a change table or
manually decompress/merge values. Logical coordinates still isolate each
occurrence of shared data. The compressed base remains byte-for-byte unchanged.

SOV2 contains one combined sparse change packet instead of separate dense-shaped
replacement and deletion packets. The outer header remains 128 bytes and binds
the snapshot to the base hash, generation and dimensions. Its SPC1 child has a
64-byte root and the same symmetric spatial branching and translated child
references used in the earlier experiment. Only regions containing changes
are built. Encoding no longer allocates full-sized sparse value and deletion
arrays; it groups the latest coordinate changes into occupied leaves directly.
The inherited writer still materializes the original base for no-op/revert
detection. Optimizing that initialization is outside this retrieval attempt.

Each leaf contains an exact changed-slot index, deletion information and a
packed vector of replacement values. The index uses sorted 16-bit slot codes
for small counts (high bit marks deletion), or a 512-bit change mask plus an
optional deletion mask when shorter. There are at most 32 sparse codes without
deletions, or 64 with deletions; larger sets use the bitmaps. The leaf's first
replacement value becomes its incoming anchor, so its first normalized value
is implicit zero. Only the remaining live values need payload bytes. The old
native raw/SNZ/SFL/SNZ(SFL) selection encodes that compact tail exactly.

Read the slot index before requesting any values. Intersect it with the query,
derive the live-value rank of each matching slot, and retrieve only those
values. Raw tails permit individual 8-byte reads. Compressed tails decode only
the stored changed values in that leaf, not a padded 512-value array. Deletes
need no value payload. An unchanged point reads no replacement values; a fully
overridden point or selection can skip the original base. Equal encoded leaves
and branches retain exact sharing, with value translations on incoming edges.
